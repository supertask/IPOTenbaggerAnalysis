# 保有銘柄の読み解きと総括を書く

`data/meta/business_profile.tsv` に1銘柄1行。画面では3つに分かれて出る。

| 出す場所 | 中身 |
|---|---|
| 「事業の内容」カードの先頭 | 収益の源泉 / 稼ぎ方の型 / 競合との違い / 事業の弱み |
| 「役員の状況」カードの先頭 | 経営陣の経歴 / 経歴と事業の噛み合い / 経営陣の懸念 |
| 独立した「総括」カード | 判定 / 買う理由 / 持ち続ける条件 / 降りる条件 / 株価水準 |

対象は保有銘柄のみ（自分・テンバガーX・お気に入り）。全銘柄には広げない。

## いちばん大事なこと

**書き終えたら「これを読んで、自分はこの株を買うか・持ち続けるか」を自問する。**
答えられないなら、それは事業の解説であって投資の判断材料になっていない。

解説で終わっている文章にはこういう特徴がある。

- 良い点しか書いていない
- 「〜が強み」で終わり、その強みが崩れる条件が書いていない
- 株価とPERに触れていない（いくらでも買っていいことになってしまう）
- **経営陣が自社株を売っていても書いていない**

最後のものが致命的。長期で持つかどうかを決めるのに、創業者が降り始めた事実を
書かない読み解きは役に立たない。

## 手順

### 1. 判断に要る数字を全部出す

```bash
python collectors/holding_judgment_dump.py 212A
```

テンバガー条件・売上と利益の推移・株価とPERと高値からの位置・ロックアップ・
拠点あたりの採算・原価の構成・大株主と役員の持株推移・上場時の諸元・
自分の保有比率が、まとめて出る。**これを見ずに書かない。**

### 2. 有報の本文を読む

```bash
python collectors/holding_profile_dump.py 212A
```

事業の内容、役員の状況、競合の事業の内容が出る。

### 3. 使えるデータと、使えないデータ

| データ | 状態 |
|---|---|
| 有価証券報告書（XBRLと本文） | 使える。44,000件 |
| 期中の報告書（四半期・半期） | 保有銘柄のみ使える |
| 株価・出来高・PER | 使える（yfinance） |
| 上場時の諸元（社長株%・VC%・初値など） | 使える（`all_companies.tsv`） |
| **適時開示（TDnet）** | **2011〜2015年ぶんしか無い。** 直近の開示は見られない |
| 月次開示 | 収集していない |

**適時開示が古いことは書き手が黙ってはいけない。** 業績修正や大株主の異動を
拾えていないので、総括の「見たデータ」に、直近の開示は見ていないと明記する。

### 4. TSVに1行足す

| 列 | 書くこと |
|---|---|
| コード / 銘柄名 | |
| 収益の源泉 | 誰に何を売って、どこで利益が出るか。**売上構成比が有報にあれば必ず入れる** |
| 稼ぎ方の型 | ストック型 / 多店舗展開型 / 営業人員依存型 |
| 競合との違い | 競合を名指しして具体的に。1拠点あたりや原価率の数字を添える |
| 事業の弱み | 事業として崩れうる点。競合が設定されていないなら比較できていないと書く |
| 経営陣の経歴 | 社長と、事業に効いている役員の前職。年数まで |
| 経歴と事業の噛み合い | **その経歴がどの数字に出ているか** |
| 経営陣の懸念 | **持株の増減を必ず見る。** 売っていれば株数と時期を書く。同族集中・兼務過多・承継もここ |
| 判定 | 次の5つから1つ（下記） |
| 買う理由 | なぜ持つ価値があるか。数字で |
| 持ち続ける条件 | **何が続いていれば持つのか。** 確認できる指標で書く |
| 降りる条件 | **何が起きたら売るのか。** 数字とイベントで書く |
| 株価水準 | 直近PER、公開価格時PER、高値からの位置、時価総額 |
| 見たデータ | 使ったもの。見ていないもの（直近の適時開示など）も書く |
| 出所報告日 / 作成日 | |

### 判定の5段階

| 判定 | 意味 |
|---|---|
| 買い増し検討 | 事業も経営陣も良く、株価も高くない |
| 継続保有 | 持ち続ける理由がある。新規に買う水準ではない |
| 様子見 | 良い面と悪い面が拮抗。次の決算などを待つ |
| 縮小検討 | 崩れの兆候がある。比率を下げることを考える |
| 判断保留 | データが足りない。何が足りないかを書く |

**判定は忖度しない。** 保有している銘柄でも、経営陣が売っていて減益なら
そう書く。持っているから良く書く読み解きには価値がない。

### 5. 書き方の約束

- 1項目2〜3文。散文で長く書かない
- 数字は画面に出ているものと一致させる。将来ずれる細かい値は幅で書く
- 分からないことは書かない。推測を断定で書かない
- 良い点と悪い点を必ず両方書く

### 6. ついでに拠点数を確かめる

有報を読んでいるので、拠点数の抽出が合っているかも見る。誤っていれば
`data/meta/facility_override.tsv` に書く。判定の癖は `facility-count` スキル。

### 7. 確認する

```bash
python -m visualizer.app
python scripts/verify_visualizer_deep.py
```

3箇所（事業カード・役員カード・総括カード）に出ることと、スマホ幅で
崩れないことを見る。

## 参考になる書き方

フィットイージー(212A)の総括を見るのが早い。書いた時点で

- 1店舗あたり利益は競合中央値の3.0倍、原価の79%が仕入で社長は内装35年
- 一方で創業社長が個人保有株の56%（181万株）を上場2年目に売却している
- 開発売上62.6%は出店時の一時収益で、ストックではない
- PER32倍は公開価格時20.8倍から切り上がり、高値から89%の位置

という良い面と悪い面が同時に立っている。**どちらか片方だけを書かない。**

## やってはいけないこと

- 全銘柄に広げる（トークンが持たない。保有銘柄以外は将来 OpenRouter の無料モデル）
- 抽出した数字と混ぜる。画面では「AIによる解釈」のバッジで区別している
- 判定を書かずに解説だけ置く
- 経営陣の持株の増減を見ずに「長期保有」と書く
