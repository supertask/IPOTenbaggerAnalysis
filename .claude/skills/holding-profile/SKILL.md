# 保有銘柄の読み解きを書く

詳細ページに出る「事業と経営陣の読み解き」カードの中身を書く手順。
`data/meta/business_profile.tsv` に1銘柄1行。書いた銘柄にだけカードが出る。

対象は保有銘柄のみ（自分・テンバガーX・お気に入り）。全銘柄には広げない。

## なぜ人が読むのか

数字の抽出では届かない線をつなぐため。フィットイージーで言えば

- 抽出で分かること … 原価の79.1%が仕入、労務費3.5%、1店舗あたり利益9.74百万（競合の3.0倍）
- 有報を読んで分かること … 社長が内装・建築で35年、出店コスト削減5項目が建材の海外直接大量仕入れ

この2つが結びついて初めて「なぜ1店舗あたり利益が競合の3倍なのか」に届く。
**片方だけ書いても意味がない。数字と経歴を必ず結びつけること。**

## 手順

### 1. 材料を出す

```bash
python collectors/holding_profile_dump.py 9166 3496 7191   # 3銘柄ずつが読みやすい
python collectors/holding_profile_dump.py --list           # 保有銘柄と競合数の一覧
```

有報の「事業の内容」「役員の状況」と、競合企業の「事業の内容」が出る。

### 2. 数字を手元に置く

読み解きは画面の数字と噛み合っていないと意味がない。同じ銘柄について

```bash
python -c "import sys; sys.path.insert(0,'.'); from visualizer import db,facility_service,tenbagger_criteria; \
c=db.get_conn(); code='9166'; \
peers=[dict(code=r['competitor_code'],name=r['competitor_name']) for r in c.execute('SELECT competitor_code,competitor_name FROM competitors WHERE company_code=? ORDER BY rank',(code,))]; \
v=facility_service.get_facility_view(code,peers); \
print('拠点', v['own']['latest'] if v else None); \
print('原価', v['cost_structure'] if v else None)"
```

を見て、1拠点あたり利益・原価率・仕入比率を把握してから書く。

### 3. TSVに1行足す

列は固定。順番も変えない。

| 列 | 書くこと |
|---|---|
| コード | 銘柄コード4桁 |
| 銘柄名 | 短い通称でよい |
| 収益の源泉 | 誰に何を売って、どこで利益が出ているか。**売上構成比が有報にあれば必ず入れる** |
| 稼ぎ方の型 | ストック型 / 多店舗展開型 / 営業人員依存型 のどれか（テンバガー条件2に対応） |
| 競合との違い | 競合を名指しして具体的に。1拠点あたりの数字があれば添える |
| 経営陣の経歴 | 社長と、事業に効いている役員の前職。年数まで書く |
| 経歴と事業の噛み合い | **その経歴がどの数字に出ているか**。ここが本体 |
| 気をつける点 | 崩れるとしたらどこか。一時収益・人依存・多角化など |
| 出所報告日 | 使った有報の提出日 |
| 作成日 | 書いた日 |

書き方の約束

- 1項目2〜3文。散文で長く書かない（競合と並べて読めなくなる）
- 数字は画面に出ているものと一致させる。将来ずれる細かい値は「0.1百万円台」のように幅で書く
- 分からないことは書かない。推測を断定で書かない

### 4. ついでに拠点数を確かめる

有報を読んでいるので、そのとき拠点数の抽出が合っているかも見る。
誤っていれば `data/meta/facility_override.tsv` に書く（拠点数を空にすれば非表示）。
判定の癖は `facility-count` スキルに書いてある。

### 5. 確認する

```bash
python -m visualizer.app
# http://127.0.0.1:5000/next_tenbagger/<コード> でカードが出るか
python scripts/verify_visualizer_deep.py
```

## 書けている例

`data/meta/business_profile.tsv` のフィットイージー(212A)を見るのが早い。
とくに「気をつける点」に

> 開発売上62.6%は出店したときに立つ一時収益で、ストックではない。
> 出店ペースが落ちると利益が直撃を受ける。

と書いてある。これは有報を読まないと出てこない指摘で、
「1店舗あたり利益が競合の3倍」という良い数字とセットで見るべきもの。
**良い点だけ並べない。**

## やってはいけないこと

- 全銘柄に広げる（トークンが持たない。保有銘柄以外は将来 OpenRouter の無料モデル）
- 抽出した数字と混ぜる。画面では「AIによる解釈」バッジで区別している
- カードを勝手に他の場所へ動かす。株主構成の下、事業情報タブの上に置いている
