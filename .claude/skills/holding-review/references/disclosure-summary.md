# 開示を読んで、なぜ動いたかを1〜2文で書く

## 目次

- なぜ要るか（規則の抜き出しとの違い）
- 書き方（長さ・入れるもの・書かないもの）
- **株主にとっての判定**（好材料／悪材料／中立／判断できない）
- 種類ごとの勘所
- TSVの列

`holding-review` の手順4-2から呼ばれる。**書き先だけが別のTSV**で、
1開示1行・URLがキーなので `business_profile.tsv` には入らない。

`data/meta/disclosure_reading.tsv` に1開示1行。出る場所は2つ。

- 詳細ページの**「株主構成」→「持株の推移」→「5%超の売買」タブ**の、理由タグの下
- **株価チャートの右（スマホでは下）の「要約」タブ**

どちらもAI由来なので `AI` バッジが付く。

対象は保有銘柄のみ（自分・テンバガーX・お気に入り）。全銘柄には広げない。

## なぜ要るか

`collectors/disclosure_summary.py` が規則で本文の一文を抜いているが、これは
**その文をそのまま出しているだけ**で、前後の文脈が要る開示だと意味が通らない。

| | 規則の抜き出し | ここで書くもの |
|---|---|---|
| 出るもの | 本文の一文そのまま | 1〜2文の要約 |
| 長さ | 130字で切る | 60〜110字 |
| 使えるとき | 「実施の目的 …を図るため。」のように1文で完結している開示 | 数字や経緯を束ねないと分からない開示 |
| 弱いところ | 途中から始まって主語が無い／数字が本文の別の場所にある | 書き手（AI）の解釈が入る |

### どこまでAIで書くか

**保有銘柄（自分・テンバガーX・お気に入り）は、画面に出る開示を全部AIで書く。**
規則の抜き出しは、書き終えるまでの繋ぎと、書き漏らしの受け皿として残す。

保有銘柄以外は今までどおり。そもそも適時開示を集めているのが保有銘柄だけなので、
それ以外の銘柄では型の固定説明（「上場時に既存株主が放出したぶん」など）が出る。
これは全銘柄に広げるとトークンが持たないという方針（`CLAUDE.md`）どおり。

対象は115件（`--dump --todo` で残りが出る）。

## 手順

### 1. 読む対象を出す

```bash
python collectors/disclosure_summary.py --dump --todo          # まだ書いていないもの
python collectors/disclosure_summary.py 212A 160A --dump       # 銘柄を指定
```

**画面に出ている開示だけ**が出る（証券会社の在庫の行は畳まれているので対象外）。
PDFの全文ではなく、目的・理由・経緯の周り1,200字だけが出る。
これで足りなければ `--chars 3000`、それでも足りなければ

```bash
python collectors/disclosure_pdf.py 212A --match 売出 --grep 目的 流通株式
```

### 2. TSVに1行足す

| 列 | 書くこと |
|---|---|
| URL | `--dump` に出ている `/disc/...` をそのまま。**これが突き合わせのキー** |
| 銘柄コード | |
| 開示日 | |
| タイトル | 開示のタイトル（そのまま） |
| 要約 | 下記 |
| 株主にとって | 好材料／悪材料／中立／判断できない（下記）。**株価の予測ではない** |
| 作成日 | |

### 3. 要約の書き方

**1〜2文、60〜110字。** 表の1行に収まる長さ。

必ず入れるもの。

1. **何をしたか**（誰が・何株・いくらで）
2. **なぜか**（会社が書いている理由）
3. **株主にとって何を意味するか**（1つだけ、書いてあることから言える範囲で）

```
◯ 上場基準の流通株式比率35%を満たすため、社長の國江仙嗣が150万株を売出し。
  議決権は68.9%→55.3%で支配は維持。換金目的ではない。

× 当社は新株式発行及び株式売出しを実施することといたしました。
  （何も足していない。タイトルと同じ）

× 創業者が持株を大量に手放しており、成長への自信が揺らいでいる可能性がある。
  （書いていないことを書いている）
```

### 3-2. 本が「開示から読め」と言っていること

指標の話は `holding-review/references/investor-books.md` にまとめてあるが、
**開示を読むときに効くものが1つある。**

ピーター・リンチ『株で勝つ』の売りサイン。

> 借入金が過去五回の四半期の間連続して減少していたのに、直近の四半期レポートを
> 見ると二五〇〇万ドルも増えている。

**水準ではなく向きの変化。** 減り続けていた借入金が急に増えたら、
その理由が開示に書かれているかを探す。書かれていなければ、
それ自体が「降りる条件」の材料になる（`holding-review`）。

### 4. 守ること

- **書いてあることだけ書く。** 推測は入れない。開示は会社の言い分なので、
  それを疑うかどうかは総括（`holding-profile`）の仕事
- 数字は開示に出ているものをそのまま。丸めない
- 「〜と考えられる」「〜の可能性がある」を使わない。使いたくなったら、
  それは書いてないということ
- **月次の進捗報告には要約を書かない。** 「自己株式の取得状況（途中経過）」
  「新株予約権の月間行使状況」は理由が書かれていない書類で、
  規則側でも空になる。型の説明（「会社が自社株を買った」）が出るのが正しい
- 同じ売出しについて複数の開示が出る（発表・価格決定・結果）。
  **いちばん内容のあるものだけ**に書けばよい。画面は要約のあるものを先に出す

## 株主にとっての良し悪しを判定する

要約と同じときに `株主にとって` の列を埋める。**好材料 / 悪材料 /
中立 / 判断できない** の4つから1つ。

**これは中身の良し悪しであって、株価の予測ではない。** 列名を
`株価への影響` にしていた時期があるが、名前が予測を約束してしまうので変えた。
株価がどう動いたかは画面が実測で別に出す（開示日の翌営業日と5営業日後の終値）。

**本文に書いてある数字だけで決める。その後の株価は見ない。**
見ると後知恵になり、「上がったから良い開示だった」という循環になる。

| 判定 | 当てはまるもの |
|---|---|
| **好材料** | 上方修正 / 増配 / 自己株買いの**実行**（枠の設定ではなく取得の実績） / 大口の受注・提携で金額が示されているもの |
| **悪材料** | 下方修正 / 減配・無配 / 希薄化を伴う増資 / 大株主の売出し / 減損・特別損失 / 業績予想の未定への変更 |
| **中立** | 会社自身が「影響は軽微」と書いているもの / **「〜が期待されます」しか無いもの** / 組織変更・役員異動 / 実質無償のM&A |
| **判断できない** | 月次の進捗報告で枠に対する進み具合が読めない回 / 訂正のみ / 本文から向きが決められないもの |

**「判断できない」を必ず使う。** 無理に3択へ押し込むと、根拠のない判定が並ぶ。

**会社の期待は根拠にしない。**「シナジーが期待されます」「収益の拡大が
見込まれます」は数字ではないので中立。金額・株数・比率が書いてあるときだけ
向きを付ける。

**自己株買いは「枠」と「実行」を分ける。** 枠の設定だけならまだ買っていない。
7320は取得枠を設定しながら**4か月連続で0株**だった。取得状況の開示で
「累計いくら買ったか」まで見て初めて好材料と言える。

### 判定と株価は食い違う。それでいい

実際に書いた4件と、そのあとの株価。

| 開示 | 判定 | 翌営業日 | 5営業日後 |
|---|---|---:|---:|
| 212A 上方修正＋増配 | 好材料 | +12.2% | +15.9% |
| **9166 自己株買いの終了** | **好材料** | +1.3% | **−13.4%** |
| 9166 SBIとの資本業務提携 | 中立 | +1.0% | +10.4% |
| 5592 blankpad完全子会社化 | 中立 | −0.3% | +2.9% |

**9166は10億円の枠を満額執行しており、株主にとっては好材料で間違いない。**
それでも売られたのは、「終了」＝買いの支えが消えることを市場が見たため
（開示の前日に+9.6%上げていた）。中身の良し悪しと株価の向きは別物で、
**ずれている開示ほど読む価値がある。**

判定を株価に合わせにいかないこと。合わせると後知恵になり、
「なぜそう判断したか」が消える。

### 5. 確認する

```bash
python -m visualizer.app
```

「5%超の売買」タブで `AI` バッジ付きの文が出ること。
表の1行に収まっていること（長いと行が伸びる）。スマホ幅でも見る。

## 出所を混ぜない

画面に出る数字は原則として決まった手順での抽出で、AIが書いたものではない
（`CLAUDE.md`）。ここで書くものは例外なので、必ず `AI` バッジが付く形で出す。
バッジの無い黒い文は開示本文の引用、`AI` 付きはここで書いた要約、
灰色の文は型ごとの固定の説明。**この3つを混ぜない。**
