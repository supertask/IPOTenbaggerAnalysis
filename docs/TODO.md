
## 大量保有報告書は5年で消える

`collectors/large_holding_collector.py` が集めている大量保有報告書は、
**EDINETに5年ぶんしか置かれていない**（有報は10年）。2026-08-13に調べたところ
2021-09以降は取れて2021-08以前は0件で、境目は日が経つと前に進んでいく。

## 財務指標の比較に足したい・外したいグラフ

いまnext側で17項目・16枚。`.claude/skills/metric-reading` で全部に目を通した結果。

### 足したいが、インデックスの作り直し（45分）が要る

`visualizer/build_index.py` の `_METRIC_ELEMENT_IDS` に無いタグは、
`data/output/index/visualizer.db` に入っていない。調べたところ現金の流れ・
借入・粗利・配当・BPSは**1行も入っていない**。足すならビルドし直しになる。

| 足したいもの | なぜ |
|---|---|
| 営業CF / フリーCF | 多店舗展開型は出店で先行投資が出る。**利益が現金になっているか**が本体で、黒字倒産の唯一の早期警報。`past_tenbagger/config.py` にエイリアスがコメントアウトで残っている |
| 有利子負債 | 出店を借入で回している会社は、金利上昇と成長減速が重なると詰む。いまは総資産と純資産の差でしか見えない |
| 売上総利益率 | 営業利益率だけだと、粗利が落ちたのか販管費が増えたのかが分からない |

### 足したいが、計算で作れる（インデックス不要）

| 足したいもの | なぜ |
|---|---|
| 総人員（正社員＋臨時）と臨時の比率 | **いまの「従業員一人当たり営業利益」は正社員だけで割っている。** フィットイージーは臨時が総人員の76%で、この指標が実態の4倍に出る |
| 総人員あたり営業利益 | 上の分母を直したもの。competitorとパート比率が違うと今の指標は比較にならない |

### 外すか、条件付きにしたいもの

| 外したいもの | なぜ |
|---|---|
| PEGレシオ | EPS成長率が負や小さいと発散する。実際フィットイージーは80.78倍、競合2社は-152倍・-147倍。**EPS成長率が正のときだけ描く**か外す |
| 経常利益 | 営業利益とほぼ同じ形（212Aは営業2,312・経常2,318百万）。日本固有で冗長 |
| 純資産・総資産の絶対額 | 規模の違う会社を並べると小さい会社の線が潰れる。自己資本比率とROAで足りる |
| 平均年齢 | 業種で決まる。テンバガー判定に効かない |
| 平均勤続年数 | 新興企業は必ず短い（212Aは2.3年）。会社の年齢と交絡して読めない |
| １株当たり四半期純利益（EPS） | 当期純利益EPSと同じ値が入るだけ（fallback）。表示順に両方あって紛らわしい |

テンバガー条件のうち、機械では判定しきれない3つをAIに任せたい。

### 分担の方針

- **保有銘柄（テンバガーX・自分のポートフォリオ）** … Claudeで分類し、
  `data/meta/business_model.tsv` に手で書く。数が少なく（30銘柄程度）、
  判断の質が投資判断に直結するため。
- **それ以外の全銘柄（1,300社超）** … **OpenRouterの無料モデル**で一括処理する。
  量が多くコストをかけられないので、多少精度が落ちても網羅を優先する。

### やること

1. `collectors/ipo_ai_summary.py` は現状 Groq 固定なので、OpenRouter を
   使えるようにする（`OPENROUTER_API_KEY`、モデル名を設定で切り替え）
2. 出力先 `data/output/ai_summary/all_companies.tsv` には既に
   ビジネスモデル名・参入障壁・保証数などの列があるので、その形式に合わせる
3. `visualizer/tenbagger_criteria.py` から ai_summary を読んで条件2/6/7に反映する
   （現在は `business_model.tsv` の手動分類しか見ていない）
4. 手動分類とAI分類が両方ある場合は手動を優先し、AI由来であることが
   画面で分かるようにする（根拠パネルに出典を出す）

### 注意

- 現在の `ai_summary/all_companies.tsv` は6社ぶんしか無く、visualizerからは
  参照されていない
- 6社の出力を見た限り「テンバガーになりそうか」は全社Falseで、理由に
  「情報不足」「不特定」が混じる。プロンプトの調整が要る

## 期中の持株を全銘柄に広げるか

`collectors/interim_report_collector.py` は、期中の報告書（中間期の四半期報告書・
半期報告書）から大株主を拾って持株の推移を年2回にする。ただし対象は
`data/output/portfolio/*.tsv` の保有銘柄だけに絞っている。

全上場企業に広げる場合の見積り:

- 書類数は保有32銘柄で約350件。全銘柄（4,100社超）だと数万件になり、
  EDINETへのリクエストとディスク使用量が跳ね上がる
- 第1・第3四半期報告書には大株主が載らないため、落とした書類の約2/3は
  持株の観点では空振りになる（財務指標としては使える）
- 役員の持株は期中の報告書には載らないので、増やしても大株主だけ

広げるなら、まず「一覧で見えている銘柄だけ」など段階を踏むのが無難。

## 一覧の「注目度」表示

注目度（S/A/B/C/D）は公開価格に対して初値がどれだけ上がるかの予想で、企業の
成長性とは別物。セカンダリ投資の判断材料としては誤解を招くので、表示位置を
下げるか外すかを決める。
