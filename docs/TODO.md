## 「拠点あたりの採算」を、台数・戸数にも対応させる（済み）

保証業やサブリースのように、積み上がる単位が拠点ではない業態がある。
実データで確かめたところ、**年ごとの推移まできれいに取れるのは3銘柄**。

| 銘柄 | 単位 | 推移 |
|---|---|---|
| 3496 アズーム | 受託台数 | 11,427 → 14,403 → 18,323 → 22,782 → 28,990 → 35,381台 |
| 3300 AMBITION | 管理戸数 | 20,343 → 21,681 → 24,971 → 25,224 → 27,354戸 |
| 5870 ナルネット | 管理台数 | 74,621 → 83,487 → 212,423台 |

「管理台数は」「受託台数）は」という定型の言い回しなので、拠点数と同じ仕組みで拾える。

**取れないもの。** 5843ニッポンインシュア・7320日本リビング保証・7191イントラストは、
有報の本文全体を検索しても保証件数の記載が1件も無い。保証業3社が揃って
開示していないので、この業態は諦める。保有32銘柄では拠点13＋件数系3＝16銘柄まで。

**広く取ると混ざる。** 319A「持ち込まれたM&A案件は累計2,398件」は収益の単位ではなく、
350A「最終保障供給契約の契約件数45,871件」は電力制度全体の数で自社のものではない。
`NEGATIVE_CONTEXT` と同じやり方で潰す。

やること。

- `facility_count_collector.py` に「(総)管理/受託/稼働 + 台数/戸数」の定型パターンを足す
- **テンプレートの「1拠点あたり」が直書き。** `facility.own.latest.unit` は既に来ている
- **自社が「台」で競合が「店舗」のときは「競合との比」を出さない。**
  1台あたり利益と1店舗あたり利益を比べても意味がない
- `facility_override.tsv` は `単位` 列を持っているので、そのまま使える

## 期中の持株を全銘柄に広げるか

`collectors/interim_report_collector.py` は、期中の報告書（中間期の四半期報告書・
半期報告書）から大株主を拾って持株の推移を年2回にする。ただし対象は
`data/output/portfolio/*.tsv` の保有銘柄だけに絞っている。

全上場企業に広げる場合の見積り:

- 書類数は保有32銘柄で約350件。全銘柄（4,100社超）だと数万件になり、
  EDINETへのリクエストとディスク使用量が跳ね上がる
- 第1・第3四半期報告書には大株主が載らないため、落とした書類の約2/3は
  持株の観点では空振りになる（財務指標としては使える）
- 役員の持株は期中の報告書には載らないので、増やしても大株主だけ

広げるなら、まず「一覧で見えている銘柄だけ」など段階を踏むのが無難。

## 一覧の「注目度」表示

注目度（S/A/B/C/D）は公開価格に対して初値がどれだけ上がるかの予想で、企業の
成長性とは別物。セカンダリ投資の判断材料としては誤解を招くので、表示位置を
下げるか外すかを決める。
