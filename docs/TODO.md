## IFRSの会社で、営業利益率が基準の違う数字どうしの割り算になっている（済み）

**`METRIC_ALIASES` の営業利益は `jppfs_cor:OperatingIncome`（日本基準）しか無い。**
IFRSを採用している会社は、売上だけ `jpcrp_cor:RevenueIFRSSummaryOfBusinessResults`
（連結）を拾い、営業利益は日本基準の別のタグから来るので、**営業利益率が
基準の違う数字どうしの割り算になる。**

対象は**294社**（IFRSの売上がある会社）。保有では 3774・6098・6574・9158 の4銘柄。

コンヴァノ(6574)で露見した。売上はIFRS連結155.2億なのに営業利益は単体11百万で、
**営業利益率0.07%・利益の質375倍**という数字が画面に出ていた。
業種中央値の表は日本基準の単体34.2億を見ているので、表とグラフで売上も食い違う。

正しいタグは **`jpigp_cor:OperatingProfitLossIFRS`**（有報のTSVで確認済み。
6574・9158・6098・3774の4社ぶんに50回出現）。

やること。

- `METRIC_ALIASES["営業利益"]` に `jpigp_cor:OperatingProfitLossIFRS` を足す
- **インデックスの作り直しが要る（50分）。** エイリアスに無いタグは1行も入らないため
- 売上と営業利益で基準が食い違う会社を洗い出し、揃っていなければ指標を出さない
- 直したら 6574・9158 の「数字の注意」を書き直す（いまは壊れている前提で書いてある）

## 「拠点あたりの採算」を、台数・戸数にも対応させる（済み）

保証業やサブリースのように、積み上がる単位が拠点ではない業態がある。
実データで確かめたところ、**年ごとの推移まできれいに取れるのは3銘柄**。

|---|---|---|

| 3300 AMBITION | 管理戸数 | 20,343 → 21,681 → 24,971 → 25,224 → 27,354戸 |
| 5870 ナルネット | 管理台数 | 74,621 → 83,487 → 212,423台 |

「管理台数は」「受託台数）は」という定型の言い回しなので、拠点数と同じ仕組みで拾える。

**取れないもの。** 5843ニッポンインシュア・7320日本リビング保証・7191イントラストは、
有報の本文全体を検索しても保証件数の記載が1件も無い。保証業3社が揃って

`NEGATIVE_CONTEXT` と同じやり方で潰す。

やること。

- `facility_count_collector.py` に「(総)管理/受託/稼働 + 台数/戸数」の定型パターンを足す
- **テンプレートの「1拠点あたり」が直書き。** `facility.own.latest.unit` は既に来ている

### 分担の方針

- **保有銘柄（テンバガーX・自分のポートフォリオ）** … Claudeで分類し、
  `data/meta/business_model.tsv` に手で書く。数が少なく（30銘柄程度）、
  判断の質が投資判断に直結するため。
- **それ以外の全銘柄（1,300社超）** … **OpenRouterの無料モデル**で一括処理する。
  量が多くコストをかけられないので、多少精度が落ちても網羅を優先する。

### やること

1. `collectors/ipo_ai_summary.py` は現状 Groq 固定なので、OpenRouter を
   使えるようにする（`OPENROUTER_API_KEY`、モデル名を設定で切り替え）
2. 出力先 `data/output/ai_summary/all_companies.tsv` には既に
   ビジネスモデル名・参入障壁・保証数などの列があるので、その形式に合わせる
3. `visualizer/tenbagger_criteria.py` から ai_summary を読んで条件2/6/7に反映する
   （現在は `business_model.tsv` の手動分類しか見ていない）
4. 手動分類とAI分類が両方ある場合は手動を優先し、AI由来であることが
   画面で分かるようにする（根拠パネルに出典を出す）

### 注意

- 6社の出力を見た限り「テンバガーになりそうか」は全社Falseで、理由に
  「情報不足」「不特定」が混じる。プロンプトの調整が要る

## 期中の持株を全銘柄に広げるか

`collectors/interim_report_collector.py` は、期中の報告書（中間期の四半期報告書・
半期報告書）から大株主を拾って持株の推移を年2回にする。ただし対象は
`data/output/portfolio/*.tsv` の保有銘柄だけに絞っている。

全上場企業に広げる場合の見積り:

- 書類数は保有32銘柄で約350件。全銘柄（4,100社超）だと数万件になり、
  EDINETへのリクエストとディスク使用量が跳ね上がる
- 第1・第3四半期報告書には大株主が載らないため、落とした書類の約2/3は
  持株の観点では空振りになる（財務指標としては使える）
- 役員の持株は期中の報告書には載らないので、増やしても大株主だけ

広げるなら、まず「一覧で見えている銘柄だけ」など段階を踏むのが無難。
